1. Visao Geral Da Arquitetura

O Digital Flavor e uma aplicacao web de pagina unica. O navegador carrega o React, o React Router escolhe a tela correta, o App.tsx controla o estado principal e as regras de negocio ficam nas classes de dominio. O projeto pode funcionar em modo demonstracao com localStorage ou integrado ao Supabase quando as variaveis de ambiente estao configuradas.

Node.js e o ambiente usado para rodar ferramentas de desenvolvimento. O npm le o package.json, instala pacotes e executa scripts padronizados. O projeto define comandos para desenvolvimento, build, lint, teste unitario e teste ponta a ponta.

Como isso funciona no nosso projeto

  • npm run dev sobe o Vite para abrir a aplicacao durante o desenvolvimento.

  • npm run test:e2e abre Playwright e executa fluxos reais no navegador.

7. TypeScript E Orientacao A Objetos

TypeScript adiciona tipos ao JavaScript. No Digital Flavor, ele aparece em tres pontos fortes: tipagem das props dos componentes, contratos de dados vindos do Supabase e classes de dominio orientadas a objetos.

Classe Product

// src/domain/Product.ts
export class Product {
  readonly id: string
  name: string
  category: ProductCategory
  priceCents: number
  sustainabilityScore: number
  active: boolean

  constructor(props: ProductProps) {
    if (props.priceCents < 0) {
      throw new Error('Product price cannot be negative')
    }

    this.id = props.id
    this.name = props.name
    this.category = props.category
    this.priceCents = props.priceCents
    this.sustainabilityScore = Math.max(0, Math.min(100, props.sustainabilityScore))
    this.active = props.active ?? true
  }

  updatePrice(priceCents: number) {
    if (priceCents < 0) throw new Error('Product price cannot be negative')
    this.priceCents = priceCents
  }
}

Aqui a classe protege regras do produto: preco nao pode ser negativo e pontuacao de sustentabilidade fica entre 0 e 100. A tela admin chama metodos como updatePrice, activate e deactivate em vez de alterar tudo solto.

Classe Cart

// src/domain/Cart.ts
export class Cart {
  private items = new Map<string, CartItemSnapshot>()

  addProduct(product: Product, quantity: number, stock?: InventoryItem) {
    this.assertQuantity(quantity)
    const currentQuantity = this.items.get(product.id)?.quantity ?? 0
    const nextQuantity = currentQuantity + quantity

    if (stock && nextQuantity > stock.availableQuantity) {
      throw new Error('Cart quantity exceeds available stock')
    }

    this.items.set(product.id, this.snapshot(product, nextQuantity))
  }

  get totalCents() {
    return this.listItems().reduce((sum, item) => sum + item.totalCents, 0)
  }
}

O Cart usa Map para indexar itens por produto. Isso evita duplicar o mesmo produto varias vezes e facilita atualizar quantidade e calcular total.

Tipos do banco

8. Estruturas De Dados

Alem das bibliotecas externas, o projeto implementa estruturas de dados pedidas no requisito avaliativo: lista, fila FIFO e pilha. Elas estao em src/domain/structures.ts e nos servicos de dominio.

Fila FIFO

// src/domain/structures.ts
export class Queue<T> {
  private items: T[] = []

  enqueue(item: T) {
    this.items.push(item)
  }

  dequeue() {
    return this.items.shift()
  }

  peek() {
    return this.items[0]
  }
}

FIFO significa "first in, first out": o primeiro pedido que entra e o primeiro a ser chamado para preparo. No painel admin, isso aparece quando a cantina clica em Chamar proximo.

Pilha LIFO

// src/domain/structures.ts
export class Stack<T> {
  private items: T[] = []

  push(item: T) {
    this.items.push(item)
  }

  pop() {
    return this.items.pop()
  }
}

LIFO significa "last in, first out": a ultima alteracao admin e a primeira a ser desfeita. A classe AdminActionHistory usa essa pilha para implementar Desfazer ultima alteracao.

Servicos que usam as estruturas

// src/domain/services.ts
export class OrderQueueService {
  private queue = new Queue<Order>()

  enqueue(order: Order) {
    order.advance('queued')
    this.queue.enqueue(order)
  }

  nextForPreparation() {
    const order = this.queue.dequeue()
    if (order) order.advance('preparing')
    return order
  }
}

export class AdminActionHistory {
  private stack = new Stack<AdminAction>()

  record(action: AdminAction) {
    this.stack.push(action)
  }

  undoLast() {
    const action = this.stack.pop()
    if (action) action.undo()
    return action
  }
}

O projeto tem duas formas de autenticacao. Em modo demonstracao, ele usa localStorage no navegador. Em ambiente com variaveis de Supabase, ele usa @supabase/supabase-js para login com senha, Google OAuth, redefinicao de senha e sessao persistente.

Cliente Supabase

// src/lib/supabase.ts
const supabaseUrl = import.meta.env.VITE_SUPABASE_URL
const supabaseAnonKey = import.meta.env.VITE_SUPABASE_ANON_KEY

export const isSupabaseConfigured = Boolean(supabaseUrl && supabaseAnonKey)

        persistSession: true,

As variaveis VITE_SUPABASE_URL e VITE_SUPABASE_ANON_KEY ficam no ambiente. Se nao existirem, supabase vira null e a aplicacao continua funcionando localmente.

Auth local com localStorage

// src/auth/demoAuth.ts
const studentsKey = 'digital-flavor-students'
const sessionKey = 'digital-flavor-session'

export function registerStudentAccount(account: StudentAccount) {
  const email = normalizeEmail(account.email)
  const existing = readStudentAccounts().filter((student) => student.email !== email)
  const nextAccount = { ...account, email, name: account.name.trim() }

  if (canUseStorage()) {
    window.localStorage.setItem(studentsKey, JSON.stringify([...existing, nextAccount]))
  }

  return nextAccount
}

Row Level Security

RLS e a seguranca por linha do PostgreSQL. Ela impede que um usuario leia ou altere dados que nao pertencem a ele, a menos que tenha perfil de equipe/admin. 

// Exemplo de policy
create policy "orders_select_owner_or_staff"
on public.orders
for select
to authenticated
using (
  customer_id = (select auth.uid())
  or exists (
    select 1 from public.profiles staff_profile
    where staff_profile.id = (select auth.uid())
      and staff_profile.role in ('employee', 'manager', 'admin')
  )
);

Na pratica: o aluno ve os proprios pedidos. Funcionarios, gerentes e admins podem ver pedidos para operar a fila da cantina.

Constraints de RA e CPF

// supabase/migrations/20260607202957_add_student_documents.sql
alter table public.profiles
  add column if not exists student_ra text,
  add column if not exists cpf text;

alter table public.profiles
  add constraint profiles_student_ra_format
  check (student_ra is null or student_ra ~ '^[0-9]{8}-[0-9]$');

A regra de documento existe em duas camadas: a interface valida RA/CPF antes de cadastrar, e o banco tambem protege o formato quando os dados chegam ao Supabase.

12. Supabase Edge Functions

Edge Functions sao funcoes serverless do Supabase. Elas rodam em Deno, recebem requisicoes HTTP e podem usar o token do usuario para consultar o Supabase de forma segura.

Invocacao no front-end

// src/lib/edgeFunctions.ts
export async function saveCustomerExperience(payload: CustomerExperiencePayload) {
  if (!supabase) {
    return { synced: false, reason: 'Supabase is not configured' }
  }

  const { error } = await supabase.functions.invoke('customer-preferences', {
    body: payload
  })

  if (error) {
    return { synced: false, reason: error.message }
  }

  return { synced: true }
}

Funcao customer-preferences

// supabase/functions/customer-preferences/index.ts
Deno.serve(async (req) => {
  if (req.method === 'OPTIONS') {
    return new Response('ok', { headers: corsHeaders })
  }

  const supabase = getSupabaseClient(req)
  const { data: { user }, error: userError } = await supabase.auth.getUser()

  if (userError || !user) {
    return jsonResponse({ error: 'Sessao invalida.' }, 401)
  }

  const body = await req.json()
  await supabase.from('customer_preferences').upsert({
    profile_id: user.id,
    phone: body.profile?.phone ?? '',
    default_pickup_time: body.preferences?.defaultPickupTime ?? '10:30'
  })

  return jsonResponse({ ok: true })
})

CORS compartilhado

O CORS permite que o front-end hospedado na Vercel chame as funcoes do Supabase. O projeto tambem configura verify_jwt = true em supabase/config.toml, exigindo sessao valida.

14. Testes, Qualidade E Comandos

O projeto usa camadas diferentes de validacao: TypeScript para tipos, ESLint para padrao de codigo, Vitest para testes de componentes/regras e Playwright para fluxo real no navegador.

Vitest + Testing Library + user-event

// src/App.test.tsx
import { render, screen } from '@testing-library/react'
import userEvent from '@testing-library/user-event'
import { MemoryRouter } from 'react-router-dom'
import { describe, expect, it } from 'vitest'

it('registers a client, creates an order, and shows the client position', async () => {
  const user = userEvent.setup()
  render(
    <MemoryRouter initialEntries={['/cadastro']}>
      <App />
    </MemoryRouter>
  )

  await user.type(screen.getByLabelText(/Nome completo/i), 'Aluno Teste')
  await user.click(screen.getByRole('button', { name: /Cadastrar e entrar/i }))
  expect(await screen.findByRole('heading', { name: /Cardapio para o intervalo/i }))
    .toBeInTheDocument()
})

Testing Library testa a tela como o usuario enxerga: labels, botoes e textos. user-event simula digitacao e clique. jest-dom adiciona matchers como toBeInTheDocument(). JSDOM cria um DOM falso para rodar esses testes no Node.

Resumo Para Explicar O Projeto

O Digital Flavor usa React para interface, React Router para navegacao, TypeScript para seguranca de tipos, classes de dominio para regras de negocio, Tailwind para visual responsivo, Supabase para autenticacao, banco PostgreSQL e funcoes remotas, Vercel para deploy e ferramentas de teste para garantir que aluno e admin consigam cumprir os principais fluxos.

Aluno

Entra ou cadastra, completa RA/CPF, escolhe itens, define horario e pagamento, confirma pedido e acompanha posicao.

Admin

Entra no painel, chama pedidos por ordem de chegada, marca preparo, entrega, edita estoque, preco e disponibilidade.

Dominio

Classes como Product, Cart, Order, Payment e InventoryItem concentram regras.

Dados

Modo demo usa localStorage. Modo remoto usa Supabase Auth, PostgreSQL, RLS e Edge Functions.

Frase final pronta

"Nosso projeto combina uma interface moderna em React com regras de negocio bem separadas em TypeScript, banco seguro no Supabase e deploy na Vercel. Assim, o aluno faz o pedido antecipado, a cantina organiza a fila e o estoque, e os testes garantem que os fluxos principais continuem funcionando."
